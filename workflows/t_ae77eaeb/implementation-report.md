# Implementation report — t_ae77eaeb

## Summary
Исправлена гонка в smoke-тесте `scripts/deploy.sh` (шаг 6): одиночный `curl`
заменён на цикл ожидания готовности порта — до 10 попыток с паузой 2с,
успех при HTTP 200 (ранний выход из цикла), `exit 1` с внятным сообщением
после исчерпания попыток. Dry-run сохранён: шаг 6 печатает только план,
реальные запросы не выполняются.

## Причина
После `systemctl restart interface-rag.service` `systemctl is-active` сразу
показывает `active`, но uvicorn ещё не забиндил порт 80 (~3–5с), поэтому
первый `curl` падал с `HTTP 000FAIL` — ложный сбой деплоя.

## Что изменено
- `scripts/deploy.sh`, секция `### 6. Smoke-тест` (единственное изменение):
  - apply: цикл `for i in $(seq 1 10)`; на каждой итерации
    `curl -sf http://127.0.0.1/ -o /dev/null -w '%{http_code}'` через `ssh_lxc`,
    при `FAIL` (curl не доступен / не 2xx из-за `-f`) продолжает попытку;
    при `200` — «[выполнено] smoke: HTTP 200 (сервис готов)» и `break`;
    после всех попыток без 200 — «Ошибка: smoke не прошёл после 10 попыток
    (последний ответ: HTTP ...)» и `exit 1`.
  - dry-run: `[план] цикл ожидания готовности: до 10 попыток ... с паузой 2с,
    выход при HTTP 200 (в dry-run реальные запросы не выполняются)`.
  - Константы `SMOKE_ATTEMPTS=10`, `SMOKE_INTERVAL=2` объявлены локально
    в секции smoke (шаги 0–5 и прочая логика деплоя не тронуты).

Шаги 0–5 в dry-run отработали как раньше (только план). Реальный деплой
(`--apply`) не выполнялся.

### Поведение цикла (изолированный mock, без LXC)
Тот же код ветки apply с mock-`ssh_lxc`:
- сервис готов на 3-й попытке → `попытка 3/10 → HTTP 200`, `[выполнено] ...`,
  выход из цикла, `EXIT=0`;
- сервис не готов никогда → 10 попыток `HTTP FAIL`, сообщение об ошибке
  «smoke не прошёл после 10 попыток ...», `EXIT=1`.
- Проверено, что `set -euo pipefail` не убивает скрипт на неудачном curl:
  `|| echo FAIL` в подстановке команды корректно гасит ненулевой код
  (mock «fail» прошёл все 10 итераций до `exit 1`).

## Ограничения / замечания
- В apply-режиме недоступность LXC (ssh-сбой) тоже даёт `FAIL` и после
  10 попыток `exit 1` — это корректное поведение (smoke реально не прошёл).
- Пауза `sleep 2` выполняется только между попытками (после последней —
  без лишнего ожидания).
