## 1. Резюме

Реализован режим возобновления `process_file` для не-`.md` входов (PDF/DOCX)
по утверждённой архитектуре (вариант A): **пропускаются только удалённые
API-стадии** (Яндекс-OCR и vision-распознавание), локальные PyMuPDF-стадии
(вырезка картинок/таблиц) перезапускаются детерминированно. Автодетект по
артефактам, без нового CLI-флага.

- Валидный `tmp/<stem>/yandex_result.json` → `pages` берутся из кэша, без вызова
  `send_to_yandex_ocr` и без требования `YANDEX_API_KEY`/`YANDEX_FOLDER_ID`.
- Валидные `tmp/<stem>/table_<idx>.md` (первая непустая строка — маркер
  `_TABLE_ID_MARKER_RE`) → vision пропускается; недостающие дозапускаются
  подмножеством через `recognize_tables_vision`.
- `md_text` при возобновлении — повторный `parse_yandex_json_to_md(pages)`
  (реальный парсинг кэша, без API). Этап 5 выполняется всегда. Этап 6+7 (AI)
  выполняется при `--ai`. Контракты `.md + --ai`, `--rag`-only и RAG (ADR-010)
  не менялись; записи атомарны (`safe_write`).

### 2.2 Новые функции (точные тела — из §5.2 отчёта)

`_load_cached_pages(file_tmp_dir)`:
- файла нет → `None`; не-JSON/`OSError` → `None` + warning «Кэш yandex_result.json повреждён — выполняется OCR»;
- не `list` / пустой `list` → `None`; нет ни одного элемента с непустым
  `result.textAnnotation` → `None`; иначе возвращает список страниц.

`_vision_table_missing(table_images, tmp_dir)`:
- для каждого `ti` проверяет `tmp/table_<table_idx>.md`: файла нет → missing;
  первая **непустая** строка не совпадает с `_TABLE_ID_MARKER_RE` → missing;
  иначе таблица распознана.
- Уточнение к §5.2: ключ берётся через `ti.get("table_idx")`; запись без
  `table_idx` (legacy/битый ввод) считается недостающей (не может иметь
  валидного кэша). Для реальных данных из `extract_table_images` поведение
  идентично телу из отчёта; это же уточнение сохраняет зелёным существующий
  тест `test_rag_v2.py::test_pdf_with_ai_triggers_vision_additionally`
  (его мок `extract_table_images` возвращает `[{"path": "table_1.png"}]`
  без `table_idx`).

## 3. Тесты — `firmware/tests/test_resume.py`

Новый файл, 28 тестов. Стиль как в остальном пакете (`sys.path.insert` в `src`,
русские docstring, мок сетевых функций). Мокаются `send_to_yandex_ocr`,
`recognize_tables_vision`, `_call_ai_api`, а также локальные `extract_images_from_pdf`,
`extract_table_images`, `run_script_postprocess`. `parse_yandex_json_to_md`
НЕ мокается — возобновление проверяется на реальном повторном парсинге кэша.

Покрытие (кейсы 1–10 из §8 отчёта + юнит-тесты новых функций):

1. Полный кэш → OCR/vision не вызываются, AI вызывается, `.md` создан, в логе
   «Данные Яндекса получены из кэша» и «Распознанные таблицы: 2 из 2 (из кэша)».
2. Нет `yandex_result.json` → `send_to_yandex_ocr` вызван, кэш записан, лог «Полный прогон…».
3. Битый кэш (`""`, `{}`, `[]`, не-JSON) → полный прогон OCR (parametrize).
4. Частичные `table_*.md` → `recognize_tables_vision` вызван ТОЛЬКО с недостающей
   таблицей (assert по `table_idx`), лог «не хватает 1 из 2 — дозапуск vision».
5. `table_N.md` без маркера → считается нераспознанным, дозапускается.
6. Документ без таблиц → vision-блок не выполняется, `.md` создаётся.
7. Без Яндекс-ключей + валидный кэш + `--ai` → успех, OCR не вызывается.
8. Без Яндекс-ключей + без кэша → `False`, лог с чёткой ошибкой.
9. Детерминизм: возобновлённый прогон побайтово равен полному (при одинаковом
   моке AI; эквивалентность локальной перевырезки + повторного парсинга).
10. Регрессия: `.md + --ai` (smoke) и `.md` без флагов → ошибка; `--rag`-only
    покрыт остальным пакетом (весь набор зелёный, см. §4).

Дополнительно: юнит-тесты `_load_cached_pages` (8) и `_vision_table_missing` (6),
включая «первая НЕПУСТАЯ строка» (пустые строки в начале допустимы) и запись без
`table_idx`.

### 4.5 Ad-hoc проверка изменённого поведения (tempfile-скрипт)

pytest-набор (см. §4.2–4.3).

## 5. Отклонения от архитектуры (задокументированные)

1. `_vision_table_missing` использует `ti.get("table_idx")` вместо
   `ti['table_idx']` (см. §2.2). Причина: автолечение legacy/битых артефактов —
   принцип самой архитектуры (§2.3/§7); для реальных данных поведение не
   отличается; существующий тест остаётся зелёным без правок.
2. В `main()` ранняя проверка ключей не просто смягчена, а удалена полностью
   (проверка теперь только в `process_file` в точке OCR). Это соответствует
   §5.3 («Убрать (или смягчить до log.warning)») и не меняет итоговый код
   выхода для всех сценариев.

  ```
  - Для PDF/DOCX без `YANDEX_API_KEY` или `YANDEX_FOLDER_ID` запуск завершается
    на этапе OCR, если нет валидного кэша `tmp/<stem>/yandex_result.json`; при
    наличии кэша пайплайн возобновляется из него без ключей (vision-таблицы —

    primary-ключа используется настроенный fallback, если он доступен.
  ```

  кэша»). Рекомендую применить правку AGENTS.md вручную или одобрить её.
- Возобновление зависит от `tmp/<stem>/` (OCR-кэш живёт там) — это осознанное
  следствие варианта A; принцип tmp-независимости относится к `--rag` и не
  нарушается. Принудительный полный прогон — ручное удаление
  `tmp/<stem>/yandex_result.json` (и при желании `table_*.md`).
- Живой прогон дозапуска vision по недостающим таблицам не выполнен (кэш был
  полный); ветка покрыта unit-тестами (кейсы 4–5).
