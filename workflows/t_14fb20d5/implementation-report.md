# Implementation Report — Фаза 2 (coder): реворк UI interface_RAG

Задача: `t_14fb20d5` — реворк UI (шапка, регистрация областью, MD-вьювер, настройки).
Требования: `docs/product/requirements.md` §5.0/§5.2/§5.3, решения 10–17 `docs/product/decision-log.md`,
архитектура `docs/architecture/architecture.md` §4.8/§5/§7.

## Что изменено

### 1. Шапка/оформление (решение 16, §5.0)
- `<title>` — «Оркестратор ГОСТ-базы — OCR→Markdown и семантический поиск» (`static/index.html`).
- Фавиконка `static/favicon.svg` (документ + лупа, inline SVG-файл), подключена `<link rel="icon">`.
- На странице — шапка с названием и подзаголовком «что за инструмент и для чего» (пайплайны
  OCR→Markdown и семантический поиск по базе ГОСТ/СП/СО/СНиП/ПУЭ).
- `static/style.css` полностью переписан: единый дизайн-систем (переменные цветов, карточки-области,
  формы, кнопки, бейджи, лог с цветовой подсветкой, MD-превью, диалог). Все три вкладки оформлены
  единообразно. Сырых дампов конфигов в интерфейсе нет.

### 2. «Добавить документ» — одна страница, три области (решения 10, 4, 17, §5.2)
- `static/index.html` + `static/app.js`: три визуальные области — **Загрузка / Регистрация (форма) /
  Лог и прогресс** (не пошаговые модальные окна).
- **Регистрация — статичная форма со ВСЕМИ полями схемы `documents.<slug>`** (`registration.FIELDS`):
  document_id, document_id_alt, document_type, domain, title, edition, date_enacted, date_amended,
  amended_by, source_file, status, status_reason, replaced_by_document_id, replaced_by_doc_key,
  ignore_sections. Над каждым полем — русское название + комментарий (назначение + пример, tooltip ⓘ),
  обязательные поля помечены `*`, пустые — с placeholder = имя поля. Кнопка «Зарегистрировать документ»
  внизу области.
- Vision-prefill после загрузки автоматически заполняет распознанные поля (редактируемы); при недоступности
  — сообщение и ручной ввод. Автоопределение типа документа по обозначению (ГОСТ/СП/СО/СНиП/ПУЭ) и года
  издания из номера.
- Валидация обязательных полей на клиенте (сообщение со списком недостающих).
- **Gating сохранён** (§4.4): «Зарегистрировать» активна после загрузки; «Конвертировать» — после загрузки
  и наличия ролей (server-side проверка ключей остаётся); «Добавить в базу» — только при `.md`+`_reg.yaml`
  и `write_enabled` (на dev заблокирована); «Стоп» — при активном job. Состояние читается из
  `GET /api/documents/{sid}` (+ новые поля `reg_exists`/`md_exists`) и `/api/settings/status`.
- **MD-вьювер** (решение 17): после конвертации появляются ссылки «Просмотр .md» (встроенный рендер
  Markdown-мини-конвертером: заголовки, таблицы, цитаты, списки, код, изображения через
  `/api/images/<stem>/...`) и «Скачать .md» (`GET /api/files/markdown/<stem>`).
- Лог процесса — цветовая подсветка строк (ошибки/предупреждения/успех).

### 3. Настройки (решения 11–15, §5.3)
- `static/settings.js` (новый, общий для вкладки и отдельной страницы) + `static/settings.html`
  (переписан как самостоятельная страница на том же коде). Рендер в `#settings-root`.
- Убраны сырые дампы `providers.yaml`/`.env` (`providers-view`/`env-view` удалены) — только
  структурированные поля, ключи маскированы (`••••last4`).
- **Единая кнопка «Сохранить»** вверху: одним действием пишет роли (PUT /api/settings/providers/roles
  для chat/vision/embedding/rerank), параметры графа (PUT /api/settings/search-config) и ключи
  (PUT /api/settings/env). Отдельных кнопок на секцию нет.
- **Кнопка «Обновить модели»** — реальный `POST /api/settings/providers/refresh` (запрос `/v1/models`
  ко всем провайдерам с ключом), результат по каждому провайдеру, списки моделей обновляются.
- Секции chat/vision/embedding/rerank: подпись **«Основная модель»** + чекбокс **«Fallback»** (поля
  fallback видны только при включённом чекбоксе) + пояснение назначения роли (ⓘ). В списках
  vision/embedding/rerank — только модели с соответствующим тегом. Выбранная модель, отсутствующая
  после «Обновить», не теряется (добавляется опцией).
- Синхронные роли сохранены (решения 6, 9): chat → ai_postprocess + query_processing; vision →
  table_vision + registration_vision (`config_ui.sync_role_models`).
- Секции: «Yandex OCR» (YANDEX_API_KEY, YANDEX_FOLDER_ID), «Ключи API провайдеров» (api_key_env каждого
  провайдера), «Прочие ключи» (TELEGRAM_BOT_TOKEN), «Параметры графа» (analyze_query,
  reformulate_query, ask_clarification, generate_answer с комментариями о назначении узла,
  temperature/max_tokens).
- «Добавить провайдера» — модальное окно (имя/base_url/ключ; «Тест» → скан моделей с тегами,
  «Добавить» → запись в providers.yaml + ключ в .env).

### 4. Backend (`firmware/src/app.py`) — минимальные изменения
- `GET /api/documents/{sid}`: добавлены `reg_exists`/`md_exists` для gating на клиенте.
- `PUT /api/settings/env`: защита от затирания реальных ключей маской — значения вида `••••…` не
  записываются (решение 15, §9.5 архитектуры).
- Механизм записи конфигов не менялся (остался `config_ui.write_yaml/write_env` в общий каталог).

## Локальный запуск (проверено вживую)

Сервер: `INTERFACE_RAG_ENV=dev`, порт 8099 (8081 занят инфраструктурным SearXNG), `uvicorn app:app`.
Проверено браузером (без единой ошибки JS):

1. **Три вкладки открываются** (Чат / Добавить документ / Настройки); title+фавиконка+подзаголовок есть.
2. **Регистрация**: загрузка `.md` → авто-prefill (document_id/title/domain, edition 1995 из номера,
   document_type «ГОСТ» авто); валидация обязательных (date_enacted); регистрация → slug
   `GOST_7777_…`; gating: «Зарегистрировать» активна после загрузки, «Добавить в базу» заблокирована
   на dev (`write_enabled=false`).
3. **MD-вьювер**: после создания `.md` в `base_markdown/<stem>/` появляются «Просмотр .md»/«Скачать .md»;
   встроенный рендер отдаёт заголовки, таблицу, цитату, изображение
   (`/api/images/<stem>/image/fig_1.jpg` → 200). `GET /api/files/markdown/<stem>` → 200.
4. **Настройки**: единая «Сохранить» записала роли (в `providers.yaml` появилась
   `create_markdown.registration_vision` — аддитивная синхронная роль, решение 9) и параметры графа;
   `.env` не изменился (hash совпал — маски не затёрли реальные ключи). «Обновить модели» — реальный
   запрос ко всем 5 провайдерам: 222 модели с тегами, роли целы, ошибки изолированы. Fallback-чекбокс
   скрывает/показывает поля. Ключи в UI маскированы. `static/settings.html` — самостоятельная страница
   с теми же секциями.
5. **Чат**: WS открывается, обработка clarification (reply-row) и graceful-ошибка при отсутствии
   коллекции Qdrant на dev.

## Замечания

- Dev-порт 8081 в этой среде занят SearXNG → проверка выполнена на 8099; в `config.yaml` порт не менялся.
- В ходе проверки «Обновить модели» и «Сохранить» dev-конфиги обновились штатно: `config/providers.yaml`
  получил реальные списки моделей провайдеров и роль `registration_vision`; `config/.env` не менялся.
  Это ожидаемое поведение новых кнопок, не ручная правка конфигов.
- MD-превью — лёгкий клиентский конвертер (без внешних библиотек); для точного рендера сложной вёрстки
  доступны ссылки просмотра/скачивания исходного `.md`.
- Тестовые артефакты загрузки из проверки удалены из `uploads/`.
