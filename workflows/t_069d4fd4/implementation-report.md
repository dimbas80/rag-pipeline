# Implementation report — t_069d4fd4

Исправление неверного сопоставления `fig_N` при выпадении изображений + alt-текст `rename_images`.

## Сводка

### Баг 1: `_insert_images_into_md` — сопоставление по pictures, а не по индексу

`firmware/src/pipeline.py`

Проблема: при провале вырезки части картинок (например, из 13 вырезалось 3: `fig_1`,
`fig_12`, `fig_13`) функция сопоставляла `@@IMAGE_N@@` по индексу в отсортированном
`extracted`, из-за чего `@@IMAGE_1@@` получал `fig_12` (рисунок №2 отсутствует, вырезка
провалилась), а `@@IMAGE_2@@` — `fig_13`.

Решение:
- В сигнатуру добавлен параметр `pictures: list[dict] | None = None` (список от
  `parse_yandex_json_to_md()`); позиция элемента в `pictures` = номер плейсхолдера.
- Для каждого picture (индекс N) ищется соответствующее extracted-изображение по
  `page` + `bbox.vertices` (сравнение вершин с округлением до 2 знаков).
- Найденное изображение заменяет `@@IMAGE_N@@` на `![fig_N](image/fig_N.ext)`.
- Если matching extracted нет (вырезка провалилась) — плейсхолдер очищается (пустая
  строка, без изменения числа строк, чтобы page_boundaries не сдвинулись).
- Защита: оставшиеся `@@IMAGE_\d+@@` вычищаются (создаются 1:1, но на случай расхождения).
- `pictures=None` — прежнее поведение (сортировка extracted по page/Y) для совместимости.
- Вызов в `process_file()` обновлён: `_insert_images_into_md(md_text, extracted, pictures=pictures, ...)`.

### Баг 2: `rename_images` — alt-текст для любого значения в [...]

Проблема: regex обновления alt-текста искал только литеральный `![image](...)`, но
`_insert_images_into_md` пишет `![fig_N](...)` — alt-текст не обновлялся.

Решение:
- Regex расширен: `!\[[^\]]*\]\(image/{re.escape(new_name)}\)` — alt-текст обновляется
  для любого значения в `[...]` (и `![fig_N]`, и `![image]`).
- Добавлена нормализация alt-текста для НЕпереименованных `fig_N` (имя файла уже
  совпадало с целевым): `![fig_N](image/fig_N.ext)` → `![Рисунок N](image/fig_N.ext)`.
  Иначе в финальном MD оставалась бы смесь `![fig_N]` и `![Рисунок N]` (приёмка:
  все ссылки вида `![Рисунок N](image/fig_N.png)`).
- Сигнатура `rename_images(md_text, img_dir)` не менялась.

## Ограничения

- Если extracted полностью пуст (PDF не открылся и т.п.) — поведение прежнее:
  `_insert_images_into_md` возвращает текст без изменений (плейсхолдеры остаются).
- Сопоставление picture ↔ extracted по `page` + `bbox.vertices` предполагает, что
  `extract_images_from_pdf` сохраняет тот же bbox, что и в `pictures` (так и есть:
  объект bbox пробрасывается без изменений).
