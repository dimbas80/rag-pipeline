# Implementation report — t_0ea5a29d

Исправление катастрофического бага `rename_images`: алфавитная сортировка
`fig_10` перед `fig_2` → перезапись файлов (`shutil.move` затирал оригиналы).

## Сводка

### Баг: `rename_images` уничтожал файлы при алфавитной сортировке

`firmware/src/pipeline.py`

Проблема: `img_files = sorted(...)` сортирует имена **алфавитно**, а не численно.
`"fig_10" < "fig_2"` (лексикографически), поэтому при полном извлечении
`fig_1..fig_14` порядок обработки был `[fig_1, fig_10, fig_11, ..., fig_14,
fig_2, ..., fig_9]`, и `fig_10 → fig_2` (i=1) **затирал оригинальный fig_2.png**,
`fig_11 → fig_3` затирал fig_3, и т.д. Из 14 файлов оставалось 6.

Решение:
- Добавлен модульный хелпер `_fig_num(p)` — числовой номер из имени `fig_N`
  (`fig_10` → 10), 0 для не-fig имён.
- Добавлен `_fig_sort_key(p)` — ключ сортировки `(группа, номер, имя)`:
  - `fig_N` файлы: `(0, N, name)` — **числовой порядок** (`fig_2` перед `fig_10`);
  - не-fig имена (хэши от старого экстрактора): `(1, 0, name)` — идут **после**
    всех `fig_N`, детерминированно по имени, и никогда не затирают `fig_N`.
- `img_files = sorted(..., key=_fig_sort_key)` вместо алфавитного `sorted(...)`.

Почему именно такой ключ, а не `key=_fig_num` из ТЗ как есть: `key=_fig_num`
вернул бы 0 для хэш-файлов, и в смешанной папке (`abc123.png` + `fig_1.png`)
хэш отсортировался бы ПЕРВЫМ и переименовался в `fig_1`, затирая оригинал —
тот же класс бага. Группировка «fig_N сначала, хэши после» исключает
перезапись для любого состава папки.

Свойства после фикса:
- Полное извлечение `fig_1..fig_14` → переименований **ноль** (имена уже
  правильные), alt-тексты нормализуются в `![Рисунок N]`.
- Выпадение вырезок (`fig_1, fig_3, ...`) → номера схлопываются по позиции
  (fig_3 → fig_2), без перезаписи: при числовой сортировке файл на позиции i
  имеет номер ≥ i+1, целевой `fig_{i+1}` либо свободен, либо это сам файл.
- Хэш-файлы дописываются после fig_N в свободные слоты.

Сигнатура `rename_images(md_text, img_dir)` не менялась.
