# Реализация t_b77b058f — per-chunk vision tables + AI_MAX_CHARS=80K + пост-проверка маркеров

## Резюме

Этап 6+7 в `pipeline.py` переработан: вместо склейки всех vision-таблиц в один blob
и чанкования `full_input` теперь чанкуется **только** `md_text`, а для каждого чанка
подставляются **только релевантные** эталонные таблицы (по ID-маркерам `t_pN_M`,
найденным в чанке). `AI_MAX_CHARS` поднят с 24000 до 80000. Добавлена пост-проверка
неснятых ID-маркеров после AI-прохода и лог покрытия чанков эталонами.

## Файлы изменены

- `firmware/src/pipeline.py`:
  1. `AI_MAX_CHARS = 80000` (строка 53).
  2. Новый хелпер `_table_id_sort_key(tid) -> tuple[int, int]` — сортировка ID
     `t_p1_0, t_p1_1, t_p2_0, ...` (страница, индекс; неизвестный формат → (0, 0)).
  3. Этап 6+7 (объединённый) переписан по спецификации:
     - `vision_tables: dict[str, str]` — загрузка `table_*.md`, ID из первой строки
       `<!-- t_pN_M -->` через `re.match`;
     - `md_chunks = _chunk_text(md_text, AI_MAX_CHARS)` — чанкуется только md_text;
     - для каждого чанка: `re.findall` ID-маркеров → сортировка `_table_id_sort_key`
       → подстановка только найденных эталонов (`=== Markdown-файл ===` /
       `=== Эталонные таблицы ===`), либо чистый чанк, если эталонов нет;
     - контекст из предыдущего чанка (`[Контекст] ... [/Контекст]`, последние 3
       строки), когда `i > 0`;
     - чекпойнтинг сохранён как был (те же имена файлов `tmp/.ai_checkpoints/<label>.json`,
       тот же формат списка результатов), но размер чекпойнта теперь `len(md_chunks)`;
     - после сборки результатов — лог `Чанков с эталонами: N/M`;
     - пост-проверка маркеров: `re.findall` по итоговому `md_text`; если остались
       неснятые `t_pN_M` → `log.warning("⚠ Неснятые ID-маркеры (...)")`, иначе
       `log.info("Все ID-маркеры сняты")`.
- `firmware/src/test_table_id_markers.py` — +3 теста на `_table_id_sort_key`
  (порядок по странице/индексу, многозначные числа, неизвестный формат).

## Известные ограничения

- `firmware/src/test_gap_filling.py` (untracked, 8/9 падает) — **предсуществующая
  проблема**, НЕ связана с этой задачей: тесты написаны под нереализованную
  функцию gap-filling (`ai_table`/`gap_input`, контекст `[gap ч.N]`), которой нет
  в `pipeline.py`. Проверено эмпирически: 8 failed / 1 passed были и ДО изменений
  этой задачи (см. также implementation-report t_37246615, «Известные ограничения»).
  Переписывание/удаление файла — отдельное решение, вне рамок этой задачи.
- Одно из следствий новой схемы: даже при одном чанке контекст AI-вызова теперь
  `"{file_stem} [ч.1]"` (раньше в single-call ветке был голый `file_stem`). Это
  соответствует спецификации задачи; на результат не влияет.
