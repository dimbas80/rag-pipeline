## Отклонение от буквального текста задачи (важно)

В задаче была указана строка `r"^(?:#{1,5}\s+\S|\*\*[^*]+\*\*)$"` с `$` **после** группы.
Эта буквальная строка НЕ проходит собственный критерий приёмки №1: `\S` матчит ровно один
непробельный символ, а `$` вне группы требует конец строки сразу после него, поэтому
`SECTION_BOUNDARY_RE.match("### Примеры классификации объектов")` возвращает `None`
(матчится только префикс `### П`, затем `$` требует конец строки — не сходится).

По смыслу задачи («матчит любую строку, **начинающуюся** с markdown-заголовка ИЛИ строку
целиком из **жирного текста**») `$` должна якорить только bold-ветку. Реализовано:

```python
SECTION_BOUNDARY_RE = re.compile(
    r"^(?:#{1,5}\s+\S|\*\*[^*]+\*\*$)"
)
```

- ветка заголовка: префикс строки (`#`...`#####` + пробел + непустой символ) — матчит и `## 2.1. Термины`, и `### Примеры классификации объектов`;
- bold-ветка: строка целиком из `**...**` (ровно одна пара звёзд, без звёзд внутри) — матчит `**СОДЕРЖАНИЕ**`, `**Примеры классификации объектов**`, `**2.1. Термины**`.

Все три критерия приёмки проходят (проверено исполнением, см. «Валидация»).

## Известные ограничения

- Bold-строка без звёзд внутри и целиком на строке (`**200 кА**` сама по себе) теперь
  считается границей раздела — это прямое следствие требования «строка целиком из
  **жирного текста**». Если в реальных документах такие строки-значения встречаются
  часто, потребуется отдельное уточнение (например, исключение коротких значений),
  но по задаче поведение именно такое.
- Промптовое правило 4 — текстовая инструкция LLM, её эффективность зависит от модели;
  кодом не гарантируется.
