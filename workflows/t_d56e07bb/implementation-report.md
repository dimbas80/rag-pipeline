# Implementation Report — t_d56e07bb

## Summary

В `firmware/src/qa_graph.py` добавлена возможность расчётов по формулам
из нормативных документов: новая функция `execute_calculation(answer,
timeout=5)` находит в ответе LLM все блоки ```python ... ```, исполняет
их в изолированном subprocess и вставляет результат сразу после блока
кода. Функция вызывается в узле `generate_answer` после каждого ответа
LLM (включая повторную генерацию при отсутствии цитат). В системный
промпт `generate_answer` добавлено правило 7 — «Если для ответа нужен
расчёт по формуле — напиши Python-код в блоке ```python ... ```…».

Пользователь видит в ответе: формулу, код и результат — и может
проверить вычисление.

## Как работает

1. `generate_answer` формирует ответ с формулами (промпт теперь
   подсказывает LLM писать Python-код в блоке ```python ... ```,
   числа с точкой: `1.2` а не `1,2`).
2. `execute_calculation()` исполняет все ```python-блоки в ответе.
3. Результат вставляется после блока кода:

   ```python
   r0 = 30  # требуемый радиус, м
   h = r0 / 1.2
   print(f"Высота молниеотвода h = {h:.1f} м")
   ```
   **Результат:**
   ```
   Высота молниеотвода h = 25.0 м
   ```

4. Пост-валидация цитат выполняется уже по обогащённому ответу
   (исходный текст цитат сохраняется, поэтому `has_citations` работает
   как раньше). При отсутствии цитат — перегенерация (max 1 доп.
   попытка), и `execute_calculation` вызывается снова на новом ответе.

## Новый API в qa_graph.py

- `execute_calculation(answer: str, timeout: int = 5) -> str` — поиск
  блоков `re.compile(r"```python\n(.*?)\n```", re.DOTALL)`, исполнение
  каждого через `subprocess.run(["python3", "-c", code], ...)`.
- Константы: `PYTHON_FENCE_PATTERN`, `CALC_BANNED_MESSAGE`,
  `CALC_TIMEOUT_MESSAGE`, `CALC_NO_OUTPUT_MESSAGE`.

Безопасность (по ТЗ):
- timeout 5 секунд (параметр функции, для тестов можно меньше);
- запрещены `input()` и `while True` на этапе разбора (строковая
  проверка до запуска subprocess);
- изоляция: `PYTHONPATH=""` (нет доступа к модулям проекта) + `cwd` —
  свежая `tempfile.TemporaryDirectory()` на каждый блок (нет доступа к
  файлам проекта); у процесса нет прав на сеть сверх окружения —
  полный сетевой песочница не реализуется (subprocess наследует
  окружение процесса, как и в референс-коде ТЗ);
- используется только стандартная библиотека Python (промпт это
  подчёркивает).

Обработка результатов:
- код завершился успешно → `stdout.strip()`; пустой вывод →
  `[выполнено без вывода]`;
- ненулевой код → `[Ошибка: <первые 200 символов stderr>]`;
- `TimeoutExpired` → `[Ошибка: превышено время исполнения]`;
- `input(`/`while True` → `[Ошибка: интерактивный ввод или бесконечный
  цикл запрещён]`.

Блоки с другим языком (```bash и т.п.) не исполняются; ответ без
python-блоков возвращается без изменений.

## Known limitations

- Полноценная сетевая изоляция исполняемого кода не реализована
  (subprocess наследует окружение процесса; запрещены только
  `input()`/`while True`, остальное ограничено timeout). Это
  соответствует референс-коду из ТЗ.
- Строковая проверка `while True` не ловит все бесконечные циклы
  (например, `for _ in iter(int, 1)`); защиту обеспечивает timeout.
- Регулярка требует перевод строки после ```python и перед ``` — при
  нестандартном форматировании блока (например, ```python без
  переноса) блок не распознается и возвращается как есть.
