## 2026-08-28 — пятая итерация («Удалить результат» + реворк «Провайдеры»/«Роли» + onclose «Думаю…»)

40. **«Удалить результат» — точный список артефактов и судьба `.md`.** Кнопка в
    области 3 раздела «Добавить документ» (рядом со «Стоп») удаляет промежуточные
    артефакты конвертации текущего документа: (1) каталог `tmp/<stem>/` **целиком**
    (OCR-кэш `yandex_result.json`, `raw.md`, распознанные таблицы `table_*.md`,
    сконвертированный PDF для DOCX, копия `table_images.json`); (2) каталог
    `Markdown/<stem>/image/` **целиком** (вырезанные `table_N.png` + рисунки);
    (3) `Markdown/<stem>/table_images.json`. **НЕ удаляются**: `<stem>.md`
    (проверенный Markdown — самостоятельная ценность; согласуется с решением 39 о
    переиндексации без пересохранения), `<stem>_reg.yaml`, `<stem>_chunks.jsonl`,
    `<stem>_assets.json`, исходный загруженный файл в `upload_base_dir/`, общий лог
    `tmp/Create_Markdown_VisionOCR.log`, `tmp/.ai_checkpoints/`. Последствие:
    повторная индексация (`--rag`) по сохранённому `.md` отработает без ошибок, но
    без картинок в реестре активов (`image/` отсутствует — fail-soft warning
    «реестр активов будет пустым», подтверждено `_run_rag_only`).

41. **Защита удаления провайдера.** Провайдера, назначенного в любую роль
    (`roles.*.*.provider` или `roles.*.*.fallback.provider`), удалить нельзя —
    бэкенд отклоняет с HTTP 409 и перечисляет роли, где он используется. Сначала
    надо переназначить роли. Каскадное обнуление ролей отклонено: молчаливая
    потеря ролей опаснее явного отказа.

42. **Разделение «Провайдеры и роли» → «Провайдеры» + «Роли».** «Провайдеры» —
    карточки (имя, base_url, ключ маскированно+редактируемо, список моделей с
    тегами) + «Добавить провайдера» + «Обновить модели» у каждого + «Удалить» с
    защитой (№41). «Роли» — каскадные селекты «Провайдер» → «Модель» (+ fallback)
    для каждой роли. Синхронные пары сохраняются (решения 6/9): chat →
    `ai_postprocess`+`query_processing`, vision → `table_vision`+
    `registration_vision` — одна группа, запись через `sync_role_models`.

43. **Ключи провайдеров — хранение в `.env`, представление в карточке.** Значения
    ключей остаются **только** в `config/.env` (единый источник для инъекции в чат
    и subprocess, решения 19/22). В карточке провайдера ключ показан маской
    (`••••<last4>`) и редактируется; запись — через существующий
    `PUT /api/settings/env` под именем `api_key_env`. Значения **не переносятся** в
    `providers.yaml` (там остаётся только `api_key_env` = имя переменной). Секция
    «Ключи API провайдеров» удаляется из меню настроек.

44. **Имя провайдера редактируемо (атомарное переименование); `api_key_env` — внутренний.**
    Переименование провайдера атомарно (один read-modify-write): переименование
    ключа в `providers.yaml` + переписывание всех ссылок `roles.*.*.provider` и
    `roles.*.*.fallback.provider`. `api_key_env` — внутренняя ссылка на переменную
    `.env`, в UI не отображается (генерируется при «Добавить провайдера» как
    `<NAME>_API_KEY`).

45. **«Обновить модели» per-provider.** Новый эндпоинт
    `POST /api/settings/providers/{name}/refresh` обновляет модели **только**
    указанного провайдера (скан `/models` → теги по имени), не трогая остальных.
    Переиспользует `scan_and_tag_models`. Глобальный
    `POST /api/settings/providers/refresh` остаётся в коде (совместимость/тесты),
    но глобальная кнопка из UI убрана.

46. **onclose/onerror сброс «Думаю…».** В `app.js` добавить обработчики
    `ws.onclose`/`ws.onerror`: снять индикатор «Думаю…» (`#chat-status`), сбросить
    `chat.awaitingClarification`; при жёстком обрыве показать неблокирующую
    подсказку «Соединение прервано — повторите вопрос». Бэкенд не меняется
    (сервер уже закрывает WS по исключению; `_stream_query` корректно обрывает
    producer через `stop.set()`).

## 2026-08-27 — четвёртая итерация (7 замечаний после e2e-теста)

33. **Чат — пустой ответ.** LLM может вернуть пустой/пробельный `final_answer` — тогда
    фронт показывает пустой пузырь со списком источников. Фикс: в `generate_answer`
    (`qa_graph.py`) после ретраев, если `answer.strip()` пуст — вернуть честный fallback
    («не удалось сформулировать ответ…»); страховка в `chat_api._format` (пустой answer →
    fallback, не пустой пузырь).
34. **Чат — обрезка длинного ответа.** `generate_answer.max_tokens=2048` обрезает длинные
    ответы. Поднять до 4096 в `config/search_config.yaml` (значение уже доступно в UI
    «Параметры графа»).
35. **Прод — только скрипты и конфиги.** На LXC в папках проектов лишнее
    (`firmware/tests/`, `__pycache__/`, `docs/`, `README.md`, `AGENTS.md`, `example/`,
    `snapshots/`, `.worktrees/`, `.gitignore`, `*.gitkeep`). `deploy.sh` синхронизирует
    только runtime-файлы и чистит лишнее.
36. **Телеграм-бот — как сервис.** `request_bot.py` читает удалённый
    `Build_Search_index/.env` (токен потерян). Запустить как systemd-юнит
    `interface-rag-bot.service` с `EnvironmentFile=/root/RAG/config/.env` (токен +
    allowed users + QDRANT_PATH из единого источника). enable + start.
37. **Настройки — «Прочие ключи» → «Телеграм».** Переименовать раздел; добавить поле
    `TELEGRAM_ALLOWED_USERS` (список допустимых чатов, ID через запятую).
38. **Тип документа — пополняемый.** Заменить фиксированный `<select>` на
    `<input>`+`<datalist>` (предложения ГОСТ/СП/СО/СНиП/ПУЭ + свободный ввод нового типа).
39. **Переиндексация существующего .md — не пересохранять.** Прод `upload.base_dir` = корень
    `!База_ГОСТ`; для `.md` файл и его `_ai.md` пишутся в корень, а не в
    `Markdown/<stem>/<stem>.md`. Если md уже есть в базе — индексировать без
    пересохранения; не оставлять копий в корне.

## 2026-08-27 — третья итерация (3 замечания после e2e-теста на реальном PDF)

30. **Чат — вернуть индикатор «Думаю…» + живой стриминг узлов.** После
    отправки запроса интерфейс мгновенно показывает «Думаю…» (статус-строка
    `#chat-status`), очищается на ответ/уточнение/ошибку. Первопричина молчания:
    `app.py:364` `list(session.stream(text))` материализует весь граф до первой
    отправки — `node`-события приходят пачкой уже после завершения. Заменить на
    потоковую отдачу (thread + queue), сохранив `__interrupt__`→clarification и
    финальный `_format(state)`.
31. **Чат — дедуп источников.** «Источники:» повторяют один документ (несколько
    чанков одного документа). Дедуп по `document_id` (приоритет), fallback —
    `title` (trim + case-insensitive), порядок первого вхождения. Дедуп — в
    `chat_api._format` при формировании `sources` (бэкенд — единая точка,
    тестируемо); фронт только рендерит.
32. **Шапка — переименование + короткий подзаголовок.** «Оркестратор ГОСТ-базы»
    → «База данных нормативно-технических документов» (`<h1>` и `<title>` в
    `index.html` и `settings.html`). Подзаголовок сократить до «Загрузка
    нормативных документов (ГОСТ / СП / СО / СНиП / ПУЭ) с распознаванием
    OCR→Markdown и семантическим поиском по базе.» (убрать «Три раздела: …»).

## 2026-08-27 — вторая итерация после приёмки (10 замечаний)

20. **Статус — фиксированный список «активный»/«не активный».** Список «статус»
    в форме регистрации должен раскрываться (сейчас не раскрывается) и содержать
    ровно два фиксированных значения с русскими подписями «активный» / «не
    активный». Внутреннее значение в `_reg.yaml` остаётся `active`/`inactive`
    (совместимость с пайплайном) — подписи русские, значение английское.
21. **Сообщение о регистрации — возле кнопки.** Сообщение об успехе/ошибке
    регистрации выводится возле кнопки «Зарегистрировать документ» (единая точка
    обратной связи; сейчас часть сообщений уходит в область загрузки).
22. **Права файлов в !База_ГОСТ — полный доступ.** Все создаваемые файлы/каталоги
    в `/mnt/sdb/!База_ГОСТ` (загрузка, `Markdown/`, `qdrant_data/`): каталоги
    `0777`, файлы `0666`. Конфиги интерфейса (`.env`, `*.yaml` в `config_dir`)
    сохраняют ограничительные права (`.env` — `0600`): глобальный `umask 000`
    недопустим (утечёт `.env`).
23. **ignore_sections — значения по умолчанию в поле.** Поле «Игнорируемые
    разделы» предзаполнено значениями по умолчанию («Предисловие, Содержание»),
    а не пустое.
24. **Регистрация — одна запись на документ.** `<stem>_reg.yaml` описывает ровно
    один документ. Повторная регистрация (после изменения полей) обновляет
    существующую запись, а не добавляет новый раздел с новым SLUG.
25. **Чат — одно окно, ввод внизу.** Одно окно чата с историей сообщений;
    единственная строка ввода внизу (и для запроса, и для ответа на уточняющий
    вопрос). Отдельные поля «запрос»/«ответ» убрать.
26. **Шапка — sticky.** Шапка с тремя вкладками закреплена при прокрутке
    (`position: sticky`), не уезжает вверх.
27. **Настройки — боковое меню.** Слева — меню разделов настроек; справа —
    настройки выбранного раздела (клик по пункту меню открывает раздел).
28. **Prefill из _reg.yaml.** При загрузке файла: если для документа уже есть
    `<stem>_reg.yaml` — подгрузить поля регистрации из него; иначе — распознать
    первую страницу (vision-prefill).
29. **Настройка папки Qdrant.** В настройках — выбор папки с базой Qdrant
    (персистентно); интерфейс использует её и передаёт пайплайну через
    `--qdrant-path`.

## 2026-08-27 — замечания после приёмки (реворк интерфейса и прода)

10. **Регистрация — отдельная область, не пошаговые окна.** Раздел «Добавить
    документ» — одна страница с визуальными областями; регистрация — статичная
    форма со всеми полями + комментариями к полям и кнопкой «Зарегистрировать
    документ», а не интерактивные пошаговые окна.
11. **UI — единая кнопка «Сохранить» + «Обновить».** Одна кнопка сохранения на все
    настройки; «Обновить» делает запрос к провайдерам и обновляет список моделей.
12. **UI — fallback по чекбоксу.** В каждой секции модели — подпись «Основная
    модель» + чекбокс «Fallback»; настройки fallback видны только при включённом
    чекбоксе.
13. **UI — пояснения ролей.** У секций chat/vision/embedding/rerank — пояснение
    назначения роли (что это и зачем).
14. **UI — параметры узлов графа** (`search_config.yaml`) показываются в настройках
    с комментариями о назначении.
15. **UI — без сырых конфигов.** `providers.yaml`/`.env`/прочее НЕ показываются в
    интерфейсе как дампы — только структурированные поля (ключи маскированы).
16. **UI — шапка.** Фавиконка, понятное название и подзаголовок (что за инструмент
    и для чего).
17. **UI — просмотр MD.** После конвертации — вьювер `.md` (просмотр/скачивание).
18. **Прод — чистая структура.** На LXC только пайплайны + веб-интерфейс + общие
    конфиги, без `.git`/`docs`/`workflows`/`.hermes`/тестов.
19. **Прод — единый общий конфиг.** Один `providers.yaml` и один `.env` (интерфейс
    пишет в них); пайплайнам конфиг передаётся CLI-ключами (`--providers-config`,
    `--config`), ключи `.env` инжектируются в subprocess. У пайплайнов нет своих
    копий конфигов.

## 2026-08-27 — ответы пользователя на вопросы оркестратора

1. **Имя проекта** — `interface_RAG` (не `Web_Pipeline_UI`).
2. **«Стоп»** — прерывание локального процесса пайплайна. Если облачная задача
   Yandex OCR не прервётся — принимается.
3. **Qdrant: пишет только прод.** Одновременная запись в базу на dev и prod не
   выполняется (контролирует пользователь). Dev не пишет в боевую базу.
4. **Wizard по шагам.** «Добавить в базу» активна только при наличии `.md` и
   `<stem>_reg.yaml`, иначе — сообщение «завершите предыдущие шаги». Область
   интерфейса визуально разделена на шаги с подписями; кнопки следующего шага
   активны после завершения предыдущего.
5. **Добавление провайдера** — сканировать список моделей провайдера и дополнить
   `providers.yaml` с тегами; тег модели (`chat`/`vision`/`embedding`/`rerank`)
   определяется **по имени модели**.
6. **«Один провайдер»** для `ai_postprocess` и `query_processing` — пользователь
   выбирает основную чат-модель; интерфейс пишет её как дефолт в обе роли синхронно.
7. **«Показать документы в базе»** — distinct-метаданные из Qdrant.
8. **Прод** — LXC `192.0.2.21` (ssh `root:root`), порт `80`, без авторизации,
   все тесты там.
9. **Vision-модель — синхронно в обе vision-роли.** Пользователь выбирает одну
   vision-модель (секция «vision»); интерфейс синхронно пишет её в
   `create_markdown.table_vision` И `create_markdown.registration_vision`.
   Отдельного селектора «регистрация» нет.

## Ранее согласовано (из заметки «Веб-интерфейс пайплайнов (план)»)

- Папйплайны не сливаем; `interface_RAG` — тонкий веб-оркестратор поверх CLI обоих.
- Стек: FastAPI + WebSocket/SSE + статический HTML/vanilla JS (без Node/React).
- `--reg` (TTY) в вебе не работает → vision-модель на первой странице; веб пишет
  `<stem>_reg.yaml` сам; пайплайн не меняем.
- Qdrant: `create_index.py` с абсолютным `--qdrant-path ... + --strict`.
- Чат: импорт `qa_graph.py` (QAGraph run/stream), цитаты + картинки таблиц как в боте.
- Пути к пайплайнам/базе не хардкодить — конфиг деплоя (dev/prod).
- Деплой на новый LXC: bind-mount `/mnt/sdb`; прод целиком (web-ui + пайплайны + бот).
