# ADR-007: Section-aware chunking for ai_postprocess table duplication fix

**Status:** PROPOSED  
**Date:** 2026-08-01  
**Author:** architect  

---

## Problem

AI-постобработка (`ai_postprocess()`) на больших документах (>24000 символов) дублирует
таблицы в конце файла. Пример: документ СО153-34.21.122-2003 (1465 строк) — таблицы
присутствуют на своих местах И дублируются в строках 1395–1466.

**Root cause:** `_chunk_text()` (строка 2334 create_markdown.py) разбивает документ на чанки
по лимиту `AI_MAX_CHARS = 24000`, игнорируя границы разделов. Чанк может начаться
посередине раздела. AI в каждом чанке, получив неполный раздел с таблицами, применяет
пункты 13–15 промпта (объединение таблиц, вынос примечаний из ячеек, форматирование
подписей) и выносит обработанные таблицы в конец своего вывода. При сборке чанков
через `"\n\n".join(results)` таблицы дублируются.

**Почему это происходит именно с таблицами:**
Промпт содержит инструкции 13–15, которые явно предписывают AI манипулировать
таблицами — объединять, переформатировать, выносить примечания из ячеек. Эти операции
нарушают позиционную целостность таблиц. В сочетании с разрывом разделов на границе
чанков AI теряет контекст и собирает все таблицы в конце своего ответа.

---

## Decision

Двухкомпонентное решение:

### 1. `_chunk_text()` — разбивка по границам разделов

Заменить текущий алгоритм (потоковая разбивка по лимиту символов) на двухфазный:

**Фаза 1: Партиционирование текста на логические разделы**

Найти все границы разделов по regex:
```
^(?:#{1,4}\s+\d+(?:\.\d+)*\s|\*\*\d+(?:\.\d+)*\s+[^*]+?\*\*)
```
Это захватывает:
- `## 4. ЗАЩИТА`, `### 4.5. Заземление`, `#### 4.7.1. Меры защиты`
- `**1. ВВЕДЕНИЕ**`, `**2.1. Термины и определения**`, `**3.2.1.1. Общие соображения**`

**НЕ** захватывает (это не границы разделов):
- `**Исходные данные о здании и окружении**` — заголовок таблицы без номера
- `*Таблица 4.3*` — подпись таблицы

Секция = строки от заголовка (включительно) до следующего заголовка (не включительно).
Текст до первого заголовка — «преамбула», отдельная секция.

**Фаза 2: Сборка чанков из целых секций**

```
chunks = []
current = ""

for section in sections:
    if not current:
        current = section
    elif len(current) + len(section) + 2 <= max_chars:
        current += "\n\n" + section
    elif len(section) > max_chars:
        # Секция-гигант: разбить по границам параграфов
        if current:
            chunks.append(current)
            current = ""
        sub_chunks = _split_oversized_section(section, max_chars)
        chunks.extend(sub_chunks)
    else:
        chunks.append(current)
        current = section

if current:
    chunks.append(current)
```

**`_split_oversized_section()`** — fallback для секций > max_chars:
Использует существующую логику `_chunk_text()` (разбивка по пустым строкам/параграфам
с сохранением целостности таблиц и кодовых блоков).

**Сохранение обратной совместимости:**
- Существующая функция `_chunk_text()` становится `_split_oversized_section()`
- Новая функция `_chunk_text()` — обёртка: партиционирование + сборка чанков

### 2. Промпт — запрет на перемещение таблиц

**Удалить/ослабить инструкции, провоцирующие перемещение таблиц:**

- Пункт 13 (объединение таблиц): **УДАЛИТЬ** — скриптовая `merge_tables()` уже делает это
- Пункт 14 (вынос примечаний из ячеек таблиц): **УДАЛИТЬ** — скриптовая `fix_notes()` уже делает это
- Пункт 15 (форматирование подписей «Таблица N»): **УДАЛИТЬ** — скриптовая `fix_table_fig_labels()` уже делает это

**Добавить в «ЧТО НЕЛЬЗЯ»:**

```
- НЕ перемещай таблицы. Каждая таблица должна остаться на своём исходном месте
  в тексте. НЕ собирай таблицы в конце документа. НЕ меняй порядок следования
  таблиц. Таблицы НЕЛЬЗЯ выносить из раздела, к которому они относятся.
```

---

## Rationale

1. **Разбивка по границам разделов** — каждый чанк содержит целые разделы, AI видит
   полный контекст и не пытается «собрать» разрозненные таблицы.

2. **Удаление табличных инструкций из промпта** — устраняет первопричину: AI больше
   не получает указаний манипулировать таблицами. Скриптовая постобработка
   (`merge_tables`, `fix_notes`, `fix_table_fig_labels`) уже выполняет эти операции
   детерминированно и корректно.

3. **Двухкомпонентность** — каждый компонент независимо снижает вероятность бага.
   Вместе они устраняют проблему полностью.

4. **Минимальные изменения** — меняются только `_chunk_text()` и `config_ai.yaml`.
   `ai_postprocess()` и `_call_ai_api()` не трогаются.

---

## Consequences

**Положительные:**
- Таблицы больше не дублируются
- Качество AI-постобработки повышается (полный контекст раздела)
- Промпт становится короче (удалено ~5 строк табличных инструкций)
- Токенов на промпт меньше → дешевле

**Отрицательные:**
- `_chunk_text()` усложняется: двухфазный алгоритм вместо потокового
- Для документов с одной гигантской секцией (>24000 символов без подразделов)
  поведение не меняется (fallback на старую логику)
- Regex для границ разделов может не покрыть экзотические форматы заголовков

**Риски:**
- **Risk-1:** Не все форматы заголовков покрыты regex. Mitigation: если `_chunk_text()`
  не нашла ни одной границы раздела — fallback на старую логику целиком.
- **Risk-2:** Удаление пунктов 13-15 может ухудшить качество для некоторых документов,
  где скриптовая постобработка не срабатывает. Mitigation: скриптовая постобработка
  уже покрывает эти случаи; если обнаружатся пробелы — решать в скриптовой
  постобработке, не в AI-промпте.

## Alternatives Considered

### A: Только фикс промпта (без section-aware chunking)

**Отклонено.** Промпт-фикс снижает вероятность, но не устраняет корневую причину:
AI всё ещё получает неполные разделы и может принимать неверные решения о структуре.

### B: Детекция и удаление дубликатов таблиц при сборке чанков

**Отклонено.** Это лечение симптома, а не причины. Сложный и ненадёжный эвристический
код. Кроме того, таблицы могут быть легитимно похожими (одинаковые заголовки).

### C: Увеличение AI_MAX_CHARS до 100000+

**Отклонено.** Не решает проблему для документов >100K символов. Многие модели имеют
context window <100K. Дороже и медленнее.

## Implementation Scope

### Затрагиваемые файлы

| Файл | Изменение |
|------|-----------|
| `firmware/src/create_markdown.py` | `_chunk_text()`: новая двухфазная реализация, старая логика → `_split_oversized_section()` |
| `firmware/src/config_ai.yaml` | `ai_postprocess.prompt`: удалить пп. 13-15, добавить запрет на перемещение таблиц |
| `firmware/src/test_chunk_overlap_table_bbox.py` | Дополнить тесты: section-aware chunking |

### Не затрагиваются

- `ai_postprocess()` — не меняется
- `_call_ai_api()` — не меняется
- Остальные функции create_markdown.py

---

## Acceptance Criteria

1. `_chunk_text()` на тестовом документе (1465 строк) создаёт чанки, каждый из которых начинается с границы раздела (bold-заголовок с номером или `##`/`###`/`####`)
2. Промпт `ai_postprocess` не содержит инструкций по манипуляции таблицами (пп. 13-15 удалены, запрет на перемещение добавлен)
3. Повторный прогон `ai_postprocess()` на тестовом документе не создаёт дубликатов таблиц в конце файла
4. Существующие тесты `test_chunk_overlap_table_bbox.py` проходят
