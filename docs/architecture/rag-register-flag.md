# Контракт: флаг `--reg` — интерактивная авторегистрация документа в rag_config.yaml

**Статус:** спроектировано (этап проектирования, реализация — отдельная задача)
**Задача:** t_d778c08b
**Связанные:** ADR-010 (RAG v2), `docs/architecture/rag-v2-architecture.md`
**Файлы:** `firmware/src/pipeline.py`, `firmware/src/rag_config.yaml`, `firmware/src/config_ai.yaml`

---

## 1. Контекст и цель

Сейчас документ обязан быть заранее прописан в `rag_config.yaml` до запуска `--rag`:
`_find_doc_key()` (~3813) сопоставляет входной файл с `source_file`, а
`build_rag_jsonl_v2()` (~3950) кидает `ValueError`, если doc_key не найден.

`--reg` устраняет ручное редактирование каталога: после прогона пайплайна
(OCR + скриптовая постобработка + опциональная AI-постобработка `--ai`)
пользователь в пошаговом диалоге подтверждает автоматически извлечённые поля,
заполняет остальные, и запись дописывается в `rag_config.yaml`.

**Требование-инвариант:** поведение `--ai` НЕ меняется. `--ai` без `--reg`
работает ровно как раньше (байт-в-байт по коду и логам). `--reg` —
ортогональный флаг, добавляемый в четыре допустимые комбинации CLI.

## 2. Семантика флага и точки врезки

`--reg` = store_true, help: «После прогона интерактивно зарегистрировать
документ в rag_config.yaml (требует TTY)».

Коллизии имён проверены: существующие опции — `-i/--input`, `--ai`,
`--config`, `--rag`, `--rag-config`; `--reg` не совпадает и не является
префиксом ни одной из них (и наоборот), getopt-сокращения argparse не
становятся неоднозначными. Добавляется после `--rag-config` в parse_args().

Использует тот же `--rag-config` путь, что и `--rag` (отдельного флага
пути конфига для регистрации не вводим).

`--reg` выполняется ПОСЛЕ получения финального `.md` и ДО генерации RAG-файлов
(`--rag`). Это даёт естественную связку `--ai --reg --rag`: регистрация →
индексация тем же запуском.

Три потока, в каждом своя точка вызова `run_registration()`:

| Поток | Условие | Точка врезки | Источник для извлечения |
|---|---|---|---|
| pdf/docx полный | `-i file.pdf [--ai] --reg` | `process_file()`, после `safe_write(md_path)` (~5325), до `_write_rag_jsonl` (~5330) | финальный `md_text` в памяти |
| md_standalone | `-i file.md [--ai] --reg` | ветка `.md` вне Markdown/ (~5075), после AI, до RAG | `md_text` (после AI) или исходный, если `--ai` нет |
| md_rag | `-i Markdown/f/f.md --reg [--rag]` | ветка md_rag (~5049), до `_run_rag_only()` | содержимое проверенного `.md` |

Расширение двух существующих гейтов валидации (единственные правки логики
ветвления за пределами добавления вызовов `run_registration()`):

- md_rag: сейчас `if not use_rag: error(".md в Markdown/: требуется --rag")`
  (~5050) → условие становится `if not (use_rag or use_reg)`;
- md_standalone: сейчас `.md` требует `--ai` или `--rag` (~5092) →
  добавляется `--reg` как третье достаточное условие.

Это даёт валидный сценарий «документ уже сконвертирован, в конфиге его нет,
RAG упал с warning — регистрирую по готовому .md и/или сразу индексирую».

Правки `main()`:
- загружать `rag_config` при `args.rag OR args.reg`; при ошибке загрузки:
  если `--rag` — как сейчас (warning, RAG пропущен); если задан `--reg` —
  `log.error` + `sys.exit(1)` (регистрация — явно запрошенное действие,
  невозможное без конфига; при обоих флагах ошибка `--reg` приоритетна);
- передать `use_reg` и путь `args.rag_config` в `process_file()`.

Обновление конфига в памяти: `run_registration()` возвращает обновлённый
dict (или None при отказе); `process_file()` передаёт его в `_write_rag_jsonl`
/ `_run_rag_only`, чтобы `--rag` в том же запуске видел новую запись.

## 3. Классификация полей

Канонический порядок полей записи (совпадает с существующими записями
rag_config.yaml — новые записи пишутся в том же порядке):

| Поле | Класс | Источник / поведение |
|---|---|---|
| `document_id` | авто + подтверждение | LLM по голове `.md` (первичные ~50 строк); fallback — regex обозначения. Промпт «Определено: …», Enter = принять, ввод = заменить |
| `document_id_alt` | пользователь, опц. | комментарий «старое обозначение (напр. СНиП II-35-76)»; Enter = null |
| `document_type` | авто + подтверждение | префикс-regex от document_id: ГОСТ/СП/СО/СНиП/ПУЭ; не распознан — спросить с комментарием «ГОСТ, СП, ПУЭ, СО, СНиП» |
| `domain` | пользователь, опц. + LLM-подсказка | комментарий «семантика (напр. Кабели)»; в промпте «Подсказка ИИ: <domain_hint>» если LLM дал; Enter = null |
| `title` | авто + подтверждение | LLM; fallback — первая строка-заголовок `^#{1,2}` или самая длинная КАПС-строка в первых 50 строках |
| `edition` | авто + подтверждение | год из document_id (§5.2); не извлёкся — спросить с примером «2016» |
| `date_enacted` | пользователь, опц. | комментарий «дата ввода в действие, формат ГГГГ-ММ-ДД (напр. 2017-06-17)»; валидация формата; Enter = null |
| `date_amended` | пользователь, опц. | комментарий «дата последних изменений, ГГГГ-ММ-ДД»; Enter = null |
| `amended_by` | пользователь, опц. | комментарий «чем изменён (напр. Приказ Минстроя РФ № 295/пр от 18.05.2021)»; Enter = null |
| `source_file` | авто, без отдельного промпта | имя входного файла (`Path.name`), 100%; показывается в баннере и в финальном ревью |
| `status` | пользователь, дефолт active | «Статус документа [active]: »; допустимо active/inactive, иначе переспрос; Enter = active |
| `status_reason` | пользователь, обяз. при inactive | «Причина недействования (напр. "Заменён на СП 60.13330.2012")» — цикл до непустого |
| `replaced_by_document_id` | пользователь, опц. при inactive | комментарий «официальный номер преемника (напр. СП 60.13330.2012), НЕ slug»; Enter = null |
| `replaced_by_doc_key` | пользователь, опц. при inactive | комментарий «ключ каталога-преемника (slug), если известен»; Enter = null |
| `ignore_sections` | авто + подтверждение | дефолт `["Предисловие", "Содержание"]`; «Определено: Предисловие, Содержание»; ввод через запятую = заменить; Enter = принять |
| (slug записи) | авто + подтверждение | §5.1; отдельный промпт с проверкой коллизий |

При `status: active` поля `status_reason`/`replaced_by_*` не спрашиваются и
пишутся `null` (инвариант `validate_rag_config`, ADR-010b).

## 4. Алгоритм извлечения

Двухуровневый: regex-слой детерминирован и всегда доступен; LLM-слой повышает
качество `document_id`/`title`/`domain_hint`. Все извлечённые значения всё
равно проходят подтверждение пользователем, поэтому деградация LLM безопасна.

### 4.1 regex-слой (всегда)

Вход: первые 50 строк финального `.md`.

- **Обозначение (document_id):** первый матч
  `(ГОСТ\s*Р?\s*№?|СП|СО|СНиП|ПУЭ)\s*№?\s*(\d[\d.\-—–]*)`
  с нормализацией пробелов; тире допускаются любые из `-—–−`.
  Пример: `ГОСТ 18410—73`, `СП 89.13330.2016`, `СО 153-34.21.122-2003`.
- **document_type:** префикс из того же матча (группа 1), нормализованный:
  убрать «Р» и «№» — `ГОСТ Р` → `ГОСТ`; валидные значения ГОСТ/СП/СО/СНиП/ПУЭ.
- **title:** первая строка `^#{1,2}\s+(.+)` в голове; иначе самая длинная
  строка из ≥4 КАПС-слов (кириллица) в первых 50 строках; иначе None.
- **edition:** §5.2 из document_id.
- **source_file / ignore_sections:** без извлечения (дефолт).

### 4.2 LLM-слой (если доступен)

Модель/провайдер: **переиспользовать эндпоинт `ai_postprocess`** (deepseek),
но со своим коротким промптом. По конвенции проекта (test_no_hardcoded_prompts,
задача t_0786b1bb) промпты живут в конфиге — новая секция `config_ai.yaml`:

```yaml
reg_extract:
  provider: deepseek
  model: deepseek-v4-pro          # как ai_postprocess
  api_key_env: DEEPSEEK_API_KEY
  base_url: https://api.deepseek.com/v1
  fallback:                        # как ai_postprocess
    provider: anymodel
    model: glm/glm-5.2
    api_key_env: ANYMODEL_API_KEY
    base_url: https://anymodel.org/v1
  prompt: |
    Ты — библиограф нормативных документов. Ниже — начало Markdown-файла,
    полученного из OCR нормативного документа (ГОСТ/СП/СО/СНиП/ПУЭ).
    Извлеки строго в JSON без пояснений:
    {"document_id": "<официальное обозначение с тире, напр. ГОСТ 18410—73>",
     "title": "<заголовок документа КАК НАПИСАН, без кавычек>",
     "domain_hint": "<1 слово тематики, напр. Кабели>"}
    Если поле не определяется — null. Только JSON.
```

Вызов: существующий `_call_ai_api(head_text, reg_cfg)` — секция передаётся
как config (в `_call_ai_api` строка `config.get("ai_postprocess", config)`
берёт сам словарь, если ключа нет; так уже работает ai_cfg в process_file).
`_call_ai_api` НЕ менять. Парсинг ответа: первый `{...}` по
`re.search(r'\{.*\}', resp, re.S)` → `json.loads`; отказ → regex-слой.

ВАЖНО (ловушка): `_call_ai_api` при пустом `prompt` делает `sys.exit(1)`
(~3101), а при отсутствии ключей/ошибке сети — корректно возвращает None.
Поэтому вызывающая сторона ОБЯЗАНА проверить `reg_cfg.get("prompt")`
непуст ДО вызова и при пустом уйти в regex-слой с warning, не вызывая
`_call_ai_api`. Иначе пустой prompt в reg_extract уронит весь прогон
вместо деградации.

Деградация: секция `reg_extract` отсутствует / пустой prompt (проверка
выше) / нет API-ключа / ошибка сети → `log.warning`, работа продолжается
на regex-слое. `--reg` из-за LLM никогда не падает.

### 4.3 Что идёт в LLM

Первые 50 строк финального `.md` (титульный лист: обозначение + title).
Не чанковать, не отправлять весь документ — задача титульная.

## 5. Правила

### 5.1 Slug (ключ записи documents.<slug>)

Генерация из подтверждённого `document_id` + `document_type` + `domain`:

1. Префикс: карта ГОСТ→GOST, СП→SP, СО→SO, СНиП→SNIP, ПУЭ→PUE — по
   нормализованному `document_type` (базовый префикс без «Р»/«№»; §4.1);
   тип не распознан → `doc`. Префикс не зависит от наличия номера:
   «ПУЭ» без номера → `PUE`.
2. Номер: первая группа цифр в document_id (`18410` из `ГОСТ 18410—73`,
   `89` из `СП 89.13330.2016`, `153` из `СО 153-34.21.122-2003`) —
   соответствует шаблону всех существующих ключей. Замечание: legacy-каталог
   неединообразен по регистру (`GOST_18410_kabel` vs `so153_molniezashita`);
   новое правило всегда даёт верхний регистр префикса, а защита от дублей —
   не регистр, а проверка коллизий из п. 5 (slug сравнивается посимвольно).
   Номера нет (напр. ПУЭ) → часть опускается: `PUE`.
3. Хвост: первое слово domain, транслитерация (кириллица→латиница, нижний
   регистр), напр. `Кабели`→`kabel`, `Молниезащита`→`molniezashita`; domain
   null/пуст → без хвоста.
4. Сборка: `{prefix}[_{number}][_{word}]`, только `[A-Za-z0-9_]`
   (префикс в верхнем регистре, остальное в нижнем).
5. Коллизия с существующим ключом → суффикс `_2`, `_3`, … 

Проверено зондом на живом каталоге: `ГОСТ 839—80`+`Кабели` →
`GOST_839_kabel` (без коллизии); повторная регистрация `ГОСТ 18410—73`+
`Кабели` → `GOST_18410_kabel_2` (коллизия с существующим ключом
детектится суффиксом); `СП 60.13330.2012`+`Отопление` → `SP_60_otoplenie`.

Slug показывается пользователю («Ключ записи (slug): GOST_839_kabel —
Enter = подтвердить или введите свой»); ручной ввод проверяется на коллизию
(регистронезависимо) и паттерн `[A-Za-z0-9_]+`, при нарушении — переспрос.

### 5.2 Год edition из document_id

Последняя группа цифр: 4 цифры → год как есть (`2016`, `2003`, `2012`);
2 цифры → век: `73`→`1973`, `16`→`2016` (правило: ≥50 → 19xx, иначе 20xx);
иное → None. Пишется строкой в кавычках (`edition: "1973"`).

### 5.3 Идемпотентность

Перед диалогом: `_find_doc_key(input_path, rag_config)` (существующая
нормализация имён). Если запись найдена и «полностью определена» —
`document_id, title, document_type, domain, edition, date_enacted,
source_file` все не-None — вывести одно сообщение «Документ уже
зарегистрирован: <slug> — регистрация пропущена» и завершить `--reg`
успешно (никаких промптов, конфиг не трогается).

Если запись найдена, но часть полей None — режим дополнения: авто-извлечение
(`document_id`, `title`) только для None-полей с подтверждением + пошаговый
опрос только оставшихся None; заполнение точечной заменой (§6.3). Существующие
не-None значения НЕ перезаписываются и не показываются как промпты.

## 6. Безопасная запись YAML

### 6.1 Выбранная стратегия: хирургический text-append / null-fill + safe_load-гейт

Проверено на живом `rag_config.yaml` (зонд, t_d778c08b):

- **Новая запись:** текстовый блок в стиле существующих записей дописывается
  в конец файла (после `rstrip('\n')` + `'\n'`), байты существующего файла не
  меняются → все комментарии и структура сохраняются тривиально.
- **Дополнение записи:** точечная замена только строк `    field: null`
  внутри блока целевой записи (regex с якорем `^` и отступом 4); данные
  остальных записей не меняются (проверено сравнением распарсенных dict'ов).
- **Гейт:** `yaml.safe_load(новый_текст)` обязан распарситься и содержать
  ожидаемую запись с ожидаемыми значениями; иначе запись не производится,
  `log.error`, оригинал не тронут. Сломанный append (незакрытая кавычка и
  т.п.) гейт ловит (проверено).
- **Атомарность:** финальный текст через существующий `safe_write()`
  (temp-файл в той же директории + `os.replace`) — конвенция проекта.

### 6.2 Отклонённые альтернативы

- **ruamel.yaml round-trip** — отклонён: пакет не установлен в окружении
  (requirements.txt его не содержит), и эксперимент на живом конфиге показал
  157 строк diff при пустой правке (переиндентация секвенций, `null` →
  пустое значение) — недопустимый churn «документа-каталога», который
  смотрит человек. Добавление новой зависимости ради этого не оправдано.
- **Полный safe_dump всего конфига** — отклонён: уничтожает все комментарии
  каталога (а комментарии в rag_config.yaml несут документацию полей).

### 6.3 Формат добавляемого блока

Точно в стиле существующих записей (2 пробела — slug, 4 — поля, двойные
кавычки, `null` литералы, `status: active` без кавычек):

```yaml

  # ── ГОСТ 839—80 — добавлено --reg 2026-08-15 ──
  gost_839_kabel:
    document_id: "ГОСТ 839—80"
    document_id_alt: null
    document_type: "ГОСТ"
    domain: "Кабели"
    title: "КАБЕЛИ СИЛОВЫЕ С ПРОПИТАННОЙ БУМАЖНОЙ ИЗОЛЯЦИЕЙ"
    edition: "1980"
    date_enacted: "1980-01-01"
    date_amended: null
    amended_by: null
    source_file: "ГОСТ 839-80 Кабели.pdf"
    status: active
    status_reason: null
    replaced_by_document_id: null
    replaced_by_doc_key: null
    ignore_sections:
      - "Предисловие"
      - "Содержание"
```

Экранирование пользовательских значений в YAML-строках: `\` → `\\`,
`"` → `\"`, контрол-символы — вырезать. Список ignore_sections — по элементу
на строку с `      - "…"`.

При null-fill комментарий вида `# ГОСТ, СП, ПУЭ… — пользователь заполнит сам`
на заполняемой строке удаляется (он стал неактуален); комментарии других
строк не трогаются.

## 7. Интерактивный диалог: формат и последовательность

Вход в диалог: баннер

```
════ РЕГИСТРАЦИЯ ДОКУМЕНТА В rag_config.yaml ════
Файл: ГОСТ 839-80 Кабели.pdf
```

Промпты двух видов (пошагово, по одному полю за раз, порядок = §3):

**А. Подтверждение авто-значения** (requirement: «определено: <значение>,
Enter = подтвердить ЛИБО отредактировать и Enter»):

```
Определено: ГОСТ 18410—73
document_id [Enter = подтвердить / или новое значение]:
```

Пустой ввод (Enter) → принять показанное; непустой → заменить. Если
авто-значения нет — промпт превращается в Б с пометкой «не определено».

**Б. Заполнение пользователем** (с комментарием и примером; Enter = null
для необязательных):

```
domain — семантика документа (напр. «Кабели»)
Подсказка ИИ: Кабели
[Enter = пропустить / или значение]:
```

Обязательные (status при inactive, status_reason) — переспрос до непустого
валидного значения. Даты валидируются `datetime.strptime(s, "%Y-%m-%d")`
с переспросом.

Финальный гейт записи:

```
── Запись будет добавлена в rag_config.yaml: ──
  gost_839_kabel:
    document_id: "ГОСТ 839—80"
    ... (полный блок)
Записать? [Y/n]:
```

Enter/Y/y → запись (§6); n/иное → «Регистрация отменена, конфиг не изменён».
`EOFError`/`KeyboardInterrupt` в любом промпте = отмена без записи.

Результат диалога: обновлённый dict конфига (для `--rag` в этом же запуске)
или None (отказ/отмена).

## 8. Не-TTY режим

`sys.stdin.isatty()` проверяется ДО любого промпта. Если False (cron, бот,
`</dev/null`): `log.error("--reg требует интерактивного терминала (TTY); конфиг не изменён. Запустите в терминале или добавьте запись в rag_config.yaml вручную")`, конфиг не мутируется, `process_file()` возвращает False →
`main()` выходит с кодом 1. Готовые `.md`/`image/` остаются на диске —
прогон не теряется, теряется только регистрация (что и отражает exit code).

## 9. Edge-кейсы (сводно)

| Кейс | Поведение |
|---|---|
| Не-TTY + `--reg` | §8: error, конфиг не тронут, exit 1 |
| Документ уже в конфиге, поля определены | §5.3: сообщение, полный skip, успех |
| Запись есть, часть полей null | дополнение только недостающих (§5.3, §6.1) |
| Повторный прогон после успешной записи | = «уже в конфиге» (slug по source_file), дубля нет |
| LLM недоступен / секции reg_extract нет | warning, regex-слой (§4.2) |
| LLM вернул не-JSON | regex-слой |
| Обозначение не извлеклось regex'ом | промпт «не определено» — пользователь вводит |
| Slug коллизия | авто-суффикс `_2…`; ручной slug с коллизией/недопустимыми символами — переспрос |
| Пользователь прервал (Ctrl-C / EOF / n) | отмена, конфиг не изменён, `--reg`-часть = неуспех (exit 1); `.md` сохранён |
| `--reg` без `--rag` | валидно: только регистрация, RAG-файлы не генерируются |
| `--reg --rag` | регистрация до `_write_rag_jsonl`/`_run_rag_only`, RAG видит новую запись |
| rag_config.yaml не существует / битый | error + exit 1 до прогона рег-фазы (§2) |
| Введённое значение содержит `"`/`\` | экранирование при генерации YAML (§6.3) |
| `--ai` без `--reg` | код-путь не меняется вообще (инвариант) |

## 11. Тест-план (firmware/tests/test_reg_flag.py)

Вход по образцу существующих тестов: `sys.path.insert(0, .../src)`,
`import pipeline`; интерактивность мокать `monkeypatch.setattr("builtins.input", ...)`;
LLM мокать патчем `_call_ai_api`; TTY — патчем `sys.stdin.isatty`.

1. **Slug:** префикс-карта; первая группа цифр; транслит; коллизия → `_2`;
   ручной slug с недопустимыми символами → переспрос.
2. **edition:** `73`→`1973`, `16`→`2016`, `2016`→`2016`, мусор→None.
3. **Извлечение:** 3+ головы `.md` разного форматирования (обозначение
   с —/–/-, КАПС-заголовок, `#`-заголовок); LLM-JSON валидный / в ```json
   fences / битый → regex-fallback.
4. **Запись:** append-блок на копии настоящего rag_config.yaml →
   `yaml.safe_load` равен ожиданию; исходные записи/комментарии не изменены
   (байтовое сравнение префикса); битый блок → гейт отклонил, файл не
   изменён; null-fill меняет только целевые поля.
5. **Идемпотентность:** после записи повторный `run_registration` с тем же
   файлом → ни одного вызова `input()`, полный skip.
6. **Диалог:** последовательность Enter'ов = принятые авто-значения; ввод
   значения = замена; Enter на опциональном = null; invalid status/date →
   переспрос; финальное `n` → None, файл не изменён.
7. **Не-TTY:** `isatty=False` → None-результат по контракту оркестратора,
   error в логе, конфиг-файл не изменён (байтово).
8. **Регресс:** `--ai` без `--reg` — код-путь неизменен (по коду: флаг
   `use_reg` не входит в `--ai`-ветки); существующий suite зелёный:
   `cd firmware && python3 -m pytest tests/ -q --ignore=tests/test_gap_filling.py`.

## 12. Риски и замечания

- **Точность LLM-извлечения** некритична: каждое значение подтверждается
  пользователем; неверное — правится в том же промпте.
- **Тире-разнобой** (—/–/-) в обозначениях: regex толерантен, канонизируем
  как введёт пользователь (существующий каталог уже смешивает `—` в id и
  `-` в именах файлов — нормализация `_find_doc_key` это покрывает).
- **Параллельный запуск** двух `--reg`: `safe_write` атомарен, но
  last-writer-wins по содержимому; каталог — ручной инструмент, считаем
  однопользовательским (как и весь текущий CLI).
- **Опечатка пользователя в YAML-значении** — гейт ловит только синтаксис;
  семантика остаётся на пользователе (каталог просматривается в ревью §7).
