# Project State

_Last updated: 2026-08-15 — by: orchestrator — направление: пайплайн на Yandex JSON + PDF, без raw.md (решение пользователя)

## Working functionality

- PDF/DOCX/DOC → Markdown pipeline работает через Yandex Vision OCR; AI-режимы используют конфиг `config_ai.yaml`.
- Для входного `.md` в `Markdown/<stem>/` флаг `--rag` выполняет только RAG-индексацию без OCR и без изменения проверенного Markdown/`image/`.
- RAG v2 строит токен-ориентированные чанки Qwen3, `{stem}_chunks.jsonl` и `{stem}_assets.json`; производные файлы записываются атомарно.
- **Многостраничные таблицы** (полный цикл): `extract_table_images()` группирует вырезки пространственно (продолжение на след. странице + подписи «Продолжение/Окончание таблицы N») → `component_images` в `tmp/<stem>/table_images.json`; `_merge_by_component_images()` склеивает части в одну MD-таблицу; `_build_asset_registry()` восстанавливает `image_paths` (все компоненты) по имени файла после снятия ID-маркеров AI-постобработкой.
- Проверено на СП 89.13330.2016: 17 вырезок → **12 логических таблиц**; Таблица Б.1 → `image_paths = [table_3, table_4, table_5]`, Ж.1 → `[table_13, table_14, table_15]`, И.1 → `[table_16, table_17]`.
- Регрессионный прогон: `cd firmware && python3 -m pytest tests/ -q --ignore=tests/test_gap_filling.py` — **312 passed** (2026-08-15, после --reg).
- **Флаг `--reg`**: после прогона интерактивно регистрирует документ в `rag_config.yaml` (авто-поля «определено: X» с подтверждением, поля пользователя пошагово с комментарием+примером; идемпотентно; требует TTY). Связка `--ai --reg --rag` регистрирует и индексирует за один запуск.

## Recent decisions

- **Диагностика СП52 принята (2026-08-22, t_de63f7f5):** Дефект A (Таблица 4.1, 4 стр.) — три первопричины: A.1 regex `_TABLE_WORD_RE` не ловит падеж «таблицы» + layoutType TEXT/LIST; A.2 порог `bottom < page_height*0.9` режет ВСЕ склейки (bbox 4.1 заканчивается на 79–83% высоты); A.3 `_stitch_continuation_tables()` попарно-жадная, не транзитивна (цепь рвётся на 2-м подряд caption-less продолжении). Дефект B (Таблица 7.1) — AI лосс-небезопасна: потеряно 3 строки (не 2, как в задаче), колонка «№», значение «M», делимитер `\(...\)`. Фикс алгоритмический: A.1/A.2 (приоритет явной подписи над геометрией) + A.3 (транзитивность) + B.1 (детерминированный guard строк/колонок с откатом) + B.2 (нормализация `\(...\)`→`$...$`) + B.3 (инварианты в промпте).
- **Модели воркеров переведены на provod (2026-08-22):** anymodel.org лежит (HTTP 000) — coder/reviewer на cx-моделях не работали. Решение пользователя: architect=provod/glm-5.2, coder=provod/gpt-5.6-luna, reviewer=provod/glm-5.2; fallback у всех deepseek-v4-pro. Все модели проверены живым запросом /chat/completions.
- **Пайплайн работает с Yandex JSON + исходным PDF, НЕ с raw.md (2026-08-15, решение пользователя):** из JSON извлекается максимум структурного — таблицы (`tables[]`), рисунки (`pictures[]` bbox), подписи/номера «Продолжение/Окончание таблицы N» (из `blocks`, где целы), структура заголовков (`layoutType` + паттерн номера + геометрия → уровень `##/###/####`). Привязка JSON-таблицы ↔ vision-вырезки — по `(page, table_index)`, без ID-маркеров (их механика удаляется). Текстовое (LaTeX-чистка, OCR-артефакты, пробелы в числах, перенос числа) — единый проход постобработкой по финальному MD, НЕ по полям JSON (на JSON теряется порядок чтения и контекст строк). Промежуточный `raw.md` устраняется, рендер MD — один раз на выходе. Снимает Known issues: склейка «Таблицы 4.1» + неснятые ID-маркеры; убирает AI-зависимость от правил заголовков (21–24). Реализация — architect (целевая модель данных + инкрементальная миграция) → coder → reviewer; старт после освобождения пайплайна.
- **Kanban-доска**: оркестратор обязан использовать доску с именем проекта (`create_markdown_ya`), НЕ `default`; при отсутствии — создавать. Правило зафиксировано в `orchestration.yml` (секция `kanban.board.rule`) и в шаблонах `!template/{software,embedded}-project/.hermes/`.

- **ID-маркеры таблиц** (2026-08-15): `extract_table_images()` назначал id по boundingBox Yandex, а `_inject_table_ids()` пересчитывал по `page_boundaries` → на границе страницы маркер съезжал, AI-сверка резолвила в чужой vision-эталон.
